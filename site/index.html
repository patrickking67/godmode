Nine coding workflows, written once, built for Claude Code and Codex.

Godmode is one plugin: nine workflow skills and ten MCP servers that need no API key. A single build turns one set of Markdown and TypeScript sources into the plugin both engines install.

Apache-2.0. No server, no database, no telemetry. Source on GitHub

Claude Code 

/plugin marketplace add patrickking67/godmode
/plugin install godmode@godmode

Then run a workflow as /godmode:revelation.

Codex 

codex plugin marketplace add patrickking67/godmode
codex plugin add godmode@godmode

Then name a skill in your prompt: godmode:revelation.

The nine workflows

Each one is a Markdown file with the same four parts: when to use it, a numbered procedure, stop conditions and a verification step. Pick one to read what the agent is told to do.

/gospel

Explain how one file, symbol, function, flow or error works by tracing the real code path.

/revelation

Map an unfamiliar codebase or subsystem and explain how it fits together (layout, entry points, data flow, conventions, risks).

/prophecy

Write a step-by-step plan for doing a task in this repository without changing any files (the precedent to copy, the files to touch, the commands to run).

/genesis

Implement a feature or change end to end (restate the goal, match existing patterns, build in small tested steps, run the project's checks).

/summon

List the subagents available in this session and pick the best one for a task, with the exact dispatch prompt.

/judgment

Review a diff for correctness bugs, security flaws, silent failures, convention drift and missing tests, and report findings by severity.

/sanctify

Run the project's own checks (typecheck, lint, tests, build) and report pass or fail per check with the failing output.

/exorcise

Find the root cause of a bug or failing test before fixing it (reproduce, rank hypotheses, isolate, explain, apply the smallest fix, re-run).

/covenant

Create one Conventional Commit from the current changes (inspect the diff, stage explicit paths, write the message, commit as the user, confirm).

One source, two engines

Claude Code and Codex read different manifests but the same skill files. Godmode keeps one copy of everything and lets a build script write the rest. Nothing in the installable plugin is edited by hand.

Subagents and hooks for Claude Code

Five subagents and three hooks ship in the same plugin. Codex ignores the subagents and loads plugin hooks only after you review and trust them.

Subagents

  • oracle Read-only codebase reconnaissance.
  • demiurge Implements a well-scoped feature or fix.
  • inquisitor Code review, read-only.
  • arbiter Runs the project's own checks.
  • seer Finds the root cause of a failure.

Hooks

  • SessionStart Lists the workflows and subagents in context.
  • PreToolUse Asks before destructive shell commands.
  • PostToolUse Formats edited files where prettier is set up.

What keeps it honest

Every claim on this page is checked by something that runs in CI or by a command you can run yourself.

212 tests
Emitter golden output, manifest schemas, name safety, hook behavior, a lint for every skill, and this page's data.
Byte-for-byte drift check
CI rebuilds the plugin and fails if any committed file differs from what the sources produce.
Scoped permissions
Workflows pre-approve read-only tools and named git commands only. A test rejects a bare shell or edit grant.
No secrets by design
A test fails if any server definition carries an env block, a header or a key. The live check runs all ten with no credentials.
