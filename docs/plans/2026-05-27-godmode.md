# Godmode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Godmode — an Apache-2.0 super-plugin for Claude Code + Codex with hybrid SQLite memory, token economics, a Hono+React webviewer, bundled MCPs, and 17 hero slash commands — incrementally across 12 phases, each independently testable.

**Architecture:** Single TypeScript package (Approach B from the spec). Four runtime surfaces share `src/core/` (db, memory, token-meter, model-router, prompt-optimizer, budget): `src/plugin/` builds dual-engine manifests from one source, `src/server/` runs a Hono+ws daemon on `127.0.0.1:51847`, `src/web/` is a React/Vite SPA served by the same server, `src/cli/` exposes the `godmode` binary.

**Tech Stack:** Node 22, TypeScript (strict), Hono + `@hono/node-server`, `ws`, `better-sqlite3` (SQLite + FTS5), React 18 + Vite + Tailwind + shadcn/ui + Zustand, Vitest + `supertest` + React Testing Library, Playwright, ajv (schema validation), `ulidx`, Conventional Commits, pnpm.

**Roadmap mapping:**

| Roadmap                                                 | Phases                                        |
| ------------------------------------------------------- | --------------------------------------------- |
| v0.2 — core memory + token meter + Claude plugin        | Phases 0 → 5 _(full TDD detail in this plan)_ |
| v0.3 — Dashboard + Memory pages                         | Phase 6 _(task-level; replan at start)_       |
| v0.4 — Codex parity                                     | Phase 7 _(task-level)_                        |
| v0.5 — Plans + Cost pages, full CLI                     | Phase 8 _(task-level)_                        |
| v0.6 — Bundled MCPs polished, `godmode doctor` complete | Phase 9 _(task-level)_                        |
| v0.7 — Beta marketplace                                 | Phase 10 _(task-level)_                       |
| v1.0 — Stable                                           | Phase 11 _(task-level)_                       |

**Why v0.2 is detailed and v0.3+ is sketched:** v0.2 is the next ~4-6 weeks and decides the shape of everything else. Phases 6-11 happen over months; planning them at step-detail today is premature — they will be replanned (using this skill again) at the start of each phase, informed by what shipped before. The sketches give file lists, acceptance criteria, and key tests so they're actionable as subagent tasks but not over-specified.

**Subagent dispatch markers:**

- ⏸ **Sequential** — depends on prior task; do not parallelize.
- ⏩ **Parallel-safe** — independent within phase; can fan out to multiple subagents in one dispatch.

import type { MiddlewareHandler } from "hono";
export function bearerAuth(expected: string): MiddlewareHandler {
  return async (c, next) => {
    const header = c.req.header("Authorization") ?? "";
    const m = header.match(/^Bearer\s+(.+)$/);
    if (!m || m[1] !== expected) return c.json({ error: "unauthorized" }, 401);
    await next();

}

**Example pattern (observations):**

```ts
// src/server/routes/observations.ts
import { Hono } from "hono";
import { z } from "zod";
import type { DB } from "../../core/db.js";
import {
  addObservation,
  searchObservations,
  updateObservation,
  deleteObservation,
  getObservation,
} from "../../core/memory.js";
import { bus } from "../events.js";

const AddSchema = z.object({
  sessionId: z.string(),
  project: z.string().nullable(),
  type: z.string(),
  title: z.string(),
  body: z.string(),
  files: z.array(z.string()).default([]),
  tags: z.array(z.string()).default([]),
});

export function observationsRoute(db: DB) {
  const app = new Hono();
  app.get("/", (c) => {
    const u = new URL(c.req.url);
    const items = searchObservations(db, {
      q: u.searchParams.get("q") ?? undefined,
      project: u.searchParams.get("project") ?? undefined,
      type: (u.searchParams.get("type") as any) ?? undefined,
      limit: Number(u.searchParams.get("limit") ?? 50),
    });
    return c.json({ items });
  });
  app.post("/", async (c) => {
    const body = AddSchema.parse(await c.req.json());
    const id = addObservation(db, body as any);
    const obs = getObservation(db, id)!;
    bus.emit("observation.added", {
      observationId: id,
      sessionId: obs.sessionId,
      title: obs.title,
      obsType: obs.type,
    });
    return c.json({ id }, 201);
  });
  app.patch("/:id", async (c) => {
    updateObservation(db, Number(c.req.param("id")), await c.req.json());
    return c.json({ ok: true });
  });
  app.delete("/:id", (c) => {
    deleteObservation(db, Number(c.req.param("id")));
    return c.body(null, 204);
  });
  return app;
}
```

Each route ends with `git commit -m "feat(server): <name> route"`.
